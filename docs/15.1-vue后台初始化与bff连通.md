# 15.1｜Vue 3 后台管理系统初始化与 Java BFF 连通

## 一、本节目标

上一章已经在 Java BFF 中建立了组织、用户、角色和权限的基础接口，但一直使用 `curl`
操作并不适合日常管理。

从本节开始建立 `platform-web` 后台管理系统。第一小节先完成最小闭环：

1. 创建 Vue 3 + TypeScript + Vite 工程；
2. 建立后台管理系统的顶栏、侧栏和工作台；
3. Vue 只调用 Java BFF，不直接调用 Python 或数据库；
4. 通过 Java BFF 读取健康状态、组织数量和用户数量；
5. 为后面的组织、用户、角色、权限页面准备统一入口。

## 二、为什么现在进入第 15 章

14.4 已经完成角色、权限以及两张关系表的基础代码，并通过 Repository 测试确认：

## 三、系统调用边界

浏览器不能直接访问数据库，也不能绕过 Java BFF 直接访问 Python LINK 服务。

```text
Vue platform-web
        |
        | HTTP /api/v1/platform/**
        v
Java platform-bff
        |
        +---- Java 自己的 MySQL schema
        |
        +---- 通过服务发现调用 Python LINK 服务
```

这样做的原因：

- 浏览器只面对一个统一后端入口；
- 认证和权限以后集中放在 Java 平台层；
- 不在 Vue 中暴露 Python 服务地址；
- Vue 不保存数据库账号或 Nacos 账号；
- Java 与 Python 仍保持清晰的职责边界。

## 五、每个文件的作用

### 1. `package.json`

声明 Vue、Vite、TypeScript 和类型检查工具，并提供以下命令：

```text
npm run dev         启动开发服务器
npm run build       类型检查后构建生产文件
npm run type-check  只执行 TypeScript 类型检查
npm run preview     本地预览构建结果
```

### 2. `vite.config.ts`

负责 Vite 开发服务器配置。

关键代理：

```ts
proxy: {
  '/api': {
    target: 'http://127.0.0.1:8080',
    changeOrigin: true,
  },
}
```

浏览器请求：

```text
http://127.0.0.1:5173/api/v1/platform/health
```

会由 Vite 转发到：

```text
http://127.0.0.1:8080/api/v1/platform/health
```

因此当前不需要修改 Java 的 CORS 配置。

注意：代理只在 `npm run dev` 的开发环境中工作。生产部署会在以后单独学习网关或 Nginx。

### 3. `src/api/platform.ts`

集中管理 Vue 对 Java BFF 的请求和 TypeScript 类型。

它先定义 Java 的统一响应：

```ts
interface ApiResponse<T> {
  code: number
  message: string
  data: T
}
```

然后提供三个函数：

```text
getPlatformHealth()   查询 Java BFF 健康状态
getOrganizations()    查询组织列表
getPlatformUsers()    查询用户列表
```

页面不直接到处写 `fetch`，后面修改请求规则时只需修改 API 层。

### 4. `src/layouts/AdminLayout.vue`

后台公共布局，包含：

- 左侧品牌和菜单；
- 顶部页面标题；
- 当前本地管理员展示；
- 中间 `<slot />` 页面内容区域。

组织、用户、角色、权限菜单在本节只是静态入口，还没有路由和点击跳转。

### 5. `src/views/DashboardView.vue`

工作台页面。

页面挂载后使用 `Promise.all` 并行请求：

```ts
const [healthData, organizations, users] = await Promise.all([
  getPlatformHealth(),
  getOrganizations(),
  getPlatformUsers(),
])
```

然后显示：

- Java BFF 是否连接正常；
- 当前组织数量；
- 当前用户数量；
- 第 15 章后续路线。

请求失败时页面会显示错误信息和“重新尝试”按钮，而不是空白。

### 6. `src/style.css`

定义后台的颜色、间距、卡片、状态标签和响应式布局。

字体优先使用中文系统字体：

```text
PingFang SC
Microsoft YaHei
Noto Sans CJK SC
```

本节不引入大型 UI 组件库，先理解 Vue 结构、接口调用和布局关系。

## 六、启动实验

### 第一步：启动本地基础设施

在项目根目录执行：

```bash
docker compose --env-file .env.local up -d
```

不要展示或提交 `.env.local`。

### 第二步：启动 Java BFF

打开一个终端：

```bash
cd /Users/apple/vscodeproject/customs-affairs-os-python-lab/platform-bff
set -a
source ../.env.local
set +a
mvn spring-boot:run
```

看到 Java 在 `8080` 端口启动后保持该终端运行。

### 第三步：安装并启动 Vue

再打开一个终端：

```bash
cd /Users/apple/vscodeproject/customs-affairs-os-python-lab/platform-web
npm install
npm run dev
```

浏览器打开：

```text
http://127.0.0.1:5173
```

## 七、验证结果

页面正常时应看到：

```text
Java BFF：连接正常
组织数量：1
用户数量：1
```

数量来自真实 Java 接口，不是前端写死的数据。

可以打开浏览器开发者工具的 Network 面板，确认出现：

```text
GET /api/v1/platform/health
GET /api/v1/platform/organizations
GET /api/v1/platform/users
```

也可以停止 Java BFF，再点击“刷新数据”，确认页面显示明确的连接错误；重新启动 Java 后点击
“重新尝试”，页面应恢复。

## 九、本节没有做什么

本节故意不做以下内容：

- 登录页、密码和退出登录；
- JWT；
- Spring Security；
- Vue Router；
- 动态菜单；
- 真正的前端权限控制；
- 组织、用户、角色、权限的增删改查表单；
- Vue 直接调用 Python LINK 服务；
- 生产环境部署。

页面中的 `admin` 只是当前实验环境的静态展示，不代表已经完成登录认证。
